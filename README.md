# FILE-API-SAVER

REST API для хранения пользовательских файлов с использованием S3-совместимого хранилища MinIO.

Проект реализует регистрацию и аутенфикацию пользователей с помощью JWT. Каждый пользователь имеет доступ только к собственным файлам. Метаданные файлов и пользователей хранятся в PostgresSQL, а сами файлы сохраняются в MinIO.

## Возможности

- Регистрация пользователя
- Авторизация пользователя (JWT)
- Загрузка файлов
- Просмотр списка своих файлов
- Получение информации о конкретном файле
- Скачивание файлов
- Удаление своих файлов
- Администратор может просматривать и удалять файлы всех пользователей

## Использeмые технологии

- Go
- PostgresSql
- GORM
- MinIO (s3)
- JWT
- REST API

## Запуск проекта 

1. Клонировать репозиторий
 ```bash
git clone https://github.com/svladislav00-qq/FILE-API-SERVER
cd FILE-API-SERVER
```

 2. Настроить `.env`

Пример с заполнением полностью описан в .env.example

3. Запустить приложение

```bash
docker compose up -d
```

## Использования

Для использования выберите нужный метод, добавьте http://localhost:4000 и эндпоинт

| Метод | Эндпоинт | Авторизация | Описание |
|---|---|---|---|
| `POST` | `/auth/register` | Не требуется | Регистрация пользователя |
| `POST` | `/auth/login` | Не требуется | Вход и получение JWT-токена |
| `POST` | `/file` | JWT | Загрузка файла |
| `DELETE` | `/file/:id` | JWT | Удаление файла |
| `GET` | `/file/allfiles` | JWT | Получение списка файлов |
| `GET` | `/file/:id` | JWT | Получение информации о файле |
| `GET` | `/file/:id/download` | JWT | Скачивание файла |
| `GET` | `/admin/file/allfiles` | JWT + роль `admin` | Получение списка файлов администратором |
| `DELETE` | `/admin/file/:id` | JWT + роль `admin` | Удаление файла администратором |
| `GET` | `/admin/file/:id` | JWT + роль `admin` | Получение информации о файле администратором |

Для защищённых эндпоинтов передавайте токен в Headers:

```http
Authorization: Bearer <token>

Для создания модерации можно при регестрации создавать пользователя с role:"admin", прописывая в JSON. Это временная мера для теста всех возможностей самостоятельно. 

## Авторизация

После входа сервер возаращает JWT-токен.

Каждый защищенный запрос должен содержать заголовок.

```
Authorization: Bearer <token>
```
